# چک‌لیست آماده‌سازی و انتشار در کافه‌بازار

این چک‌لیست وضعیت فنی مخزن را از پیش‌نیازهای حساب توسعه‌دهنده و آزمون واقعی جدا می‌کند. تیک‌زدن موارد فقط بر اساس مدرک معتبر انجام می‌شود.

- [x] APK انتشار روی شبیه‌ساز Android نصب و اجرا شد (اجرای CI شماره 179).
- [x] بررسی‌های امنیتی سورس و مجوزهای Android موفق.
- [x] گزارش اندازه و SHA-256 فایل‌ها در artifact ساخت ثبت شد.
- [ ] تطبیق نام بسته ir.moshaver.tahsili و نسخه 1.1.1+4 با پنل بازار.
- [ ] نصب و اجرای APK روی حداقل یک گوشی واقعی.

## وضعیت فعلی تنظیمات GitHub

آخرین بررسی پیکربندی ساخت نشان می‌دهد کلید AI، نشانی سرویس و مدل تنظیم شده‌اند و چهار مقدار امضای خصوصی انتشار نیز در دسترس workflow هستند. دو ورودی زیر هنوز خالی‌اند؛ بنابراین `PRODUCTION_READY=false` است و انتشار تجاری عمداً مسدود می‌ماند:

- [ ] Secret: `BAZAAR_RSA_PUBLIC_KEY`
- [ ] Variable: `BAZAAR_CATALOG_CONFIRMED=true` (فقط پس از ساخت و تطبیق واقعی محصولات در پنل بازار)

### Secrets

- `AI_API_KEY` یا `DEEPSEEK_API_KEY` — تنظیم شده
- `BAZAAR_RSA_PUBLIC_KEY` — نیازمند دریافت از پنل توسعه‌دهندگان کافه‌بازار
- `RELEASE_KEYSTORE_BASE64` — تنظیم شده
- `RELEASE_KEYSTORE_PASSWORD` — تنظیم شده
- `RELEASE_KEY_ALIAS` — تنظیم شده
- `RELEASE_KEY_PASSWORD` — تنظیم شده
- `SIGNING_BACKUP_PASSPHRASE` — برای ساخت نسخه پشتیبان رمزگذاری‌شده باید اضافه شود؛ حداقل ۲۴ نویسه

### Variables

- `AI_API_ENDPOINT` — تنظیم شده؛ `https://api.avalai.ir/v1/chat/completions`
- `AI_MODEL` — تنظیم شده؛ `deepseek-chat`
- `BAZAAR_CATALOG_CONFIRMED=true` — پس از تأیید شناسه محصولات باید اضافه شود.

**کلید عمومی بازار را خودمان تولید نمی‌کنیم.** این مقدار باید از پنل توسعه‌دهندگان/پیشخوان بازار برای همین برنامه دریافت شود؛ کلید عمومی ساختگی یا کلید عمومی یک برنامه دیگر، اعتبارسنجی خرید را خراب می‌کند.

## پشتیبان‌گیری از کلید امضای انتشار

Workflow با نام **Export encrypted Android signing backup** به مخزن اضافه شده است:

1. در Settings → Secrets and variables → Actions یک Secret به نام `SIGNING_BACKUP_PASSPHRASE` بسازید؛ گذرواژه‌ای قوی و حداقل ۲۴ نویسه‌ای انتخاب کنید و آن را خارج از GitHub نگه دارید.
2. در Actions، workflow بالا را انتخاب و دستی اجرا کنید.
3. در ورودی تأیید دقیقاً `BACKUP_EXISTING_KEY` را وارد کنید.
4. فقط فایل رمزگذاری‌شده بارگذاری می‌شود؛ artifact هفت روز نگهداری می‌شود. آن را دانلود و دست‌کم دو نسخه آفلاین امن نگهداری کنید.

**مهم:** اگر برای تولید Keystore از PAT استفاده شده، حذف Secret موقت آن، خود PAT را باطل نمی‌کند. توکن را جداگانه از تنظیمات GitHub حساب کاربری revoke کنید. کلید امضای فعلی را دوباره تولید نکنید؛ انتشار به‌روزرسانی باید با همان کلید انجام شود.

## اندازه خروجی ساخت CI

اندازه‌های ثبت‌شده در اجرای موفق شماره 179:

| فایل | اندازه |
|---|---:|
| APK arm64 | 17.65 MiB |
| APK armv7 | 15.25 MiB |
| APK x86_64 | 18.77 MiB |
| APK universal | 48.74 MiB |
| AAB | 41.37 MiB |

برای بیشتر گوشی‌های جدید، فایل arm64 گزینه مناسب‌تری برای نصب آزمایشی است. فایل universal همه معماری‌ها را در خود دارد و بزرگ‌تر است. فایل AAB برای بارگذاری در فروشگاه است و اندازه آن معادل دانلود نهایی کاربر نیست.

Artifact ساخت با نامی شبیه `android-1.1.1-<commit>` در صفحه Actions نگهداری می‌شود (۱۴ روز). داخل ZIP، APKها، AAB و گزارش اندازه/SHA-256 قرار دارند.

## تصمیم انتشار

وضعیت فعلی: **نسخه آزمایشی امضاشده و قابل نصب؛ هنوز آماده انتشار تجاری نیست.**

تا زمان دریافت کلید عمومی بازار، تأیید کاتالوگ، پشتیبان‌گیری آفلاین از Keystore، آزمون خرید واقعی و نصب روی گوشی فیزیکی، نباید نسخه را «منتشرشده» یا «آماده انتشار تجاری» معرفی کرد.
